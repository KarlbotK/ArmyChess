# Playwright 验收记录

验收日期：2026-09-20  
验收环境：Chromium，1280 × 720，前端 `http://127.0.0.1:4173`，后端 `http://127.0.0.1:8080`

## 结论

第一轮产品化改造通过浏览器端到端验收。四个独立标签页分别以南、西、北、东四个席位进入同一房间，完成布阵、开局、完整一轮行棋、聊天和重连流程。浏览器控制台最终为 **0 error / 0 warning**。

## 已验证场景

- 创建六位房间号，另外三位玩家通过房间号加入。
- 四人到齐后进入布阵阶段，界面展示 25 枚己方棋子和全部布阵限制。
- 规则弹窗完整展示四方轮转、军旗大本营、炸弹首排限制、地雷后两排、司令阵亡亮旗、铁路、行营及胜负规则。
- 四方按“南 → 西 → 北 → 东”轮流执棋，并回到南家。
- 非当前回合玩家点击己方棋子时不会出现可走位置。
- 己方棋子显示身份，其他三方保持暗棋；公开战况只显示移动、交锋和出局，不显示交战棋子身份。
- 聊天消息从东家发送后可在南家实时看到。
- 北家刷新页面后恢复原座位和当前棋局。
- 投降操作存在不可误触的二次确认，并可取消继续对局。
- 1280 × 720 下布阵面板不会拦截棋盘棋子的点击。

## 第二轮验收

- 布阵限制能够识别军旗离开大本营等非法阵型，服务端拒绝非法提交。
- 四方提交后，服务端下发 30 秒截止时间，所有客户端显示同步倒计时。
- 南家不操作至超时后，服务端自动切换到西家，并广播“南家超时，自动跳过（1/5）”；这不是仅在前端运行的动画。
- 南家与北家先后投降后，四个客户端均进入结算；南北视角显示失败，东西视角显示胜利。
- 结算仅展示获胜队伍，没有展示任何交战棋子身份。
- 四位玩家依次确认“再来一局”，准备数从 0/4 递增；第四票后原房间清空旧棋盘并回到全员重新布阵。
- 第二轮结束时浏览器控制台仍为 **0 error / 0 warning**。

## 第三轮规则拦截回归

- 重启到最新后端后重新创建房间，四个独立标签页完成南、西、北、东四方入座。
- 地雷与第一排司令交换时，界面直接显示“地雷只能放在最后两排，已禁止交换”，棋子位置不变，确认布阵仍可用。
- 炸弹与第一排司令交换时，界面直接显示“炸弹不能放在第一排，已禁止交换”，不再先形成非法阵型再提示。
- 浏览器控制台为 **0 error / 0 warning**。
- 补充前后端双端规则回归测试：铁路普通棋子经过弯道时，任一转弯节点有棋子占用均不得绕过；覆盖“第二排炸弹绕过第一排司令”的原始复现场景。

## 第四轮工兵与出局原因回归

- 工兵寻路改为每次选中只计算一次铁路可达域；前后端均覆盖多次转弯、单点受阻后的合法绕行、所有出口受阻、可攻击终点敌棋但不得穿越等场景。
- 夺旗行动依次产生脱敏交锋事件与 `FLAG_LOST` 出局事件，战况显示“军旗被擒获，全军覆没”，不包含进攻棋子。
- 轮转时发现玩家没有任何合法移动会产生 `NO_LEGAL_MOVE` 出局事件，战况显示“无棋可走，全军覆没”。
- Playwright 验证规则弹窗已明确展示工兵可转弯、绕行但不能穿棋，以及两种全军覆没原因；工兵棋子可正常选中，浏览器控制台为 **0 error / 0 warning**。

## 第五轮路线显示与重启恢复

- 固定工兵场景 `?demo=1&scenario=sapper-route` 自动选中位于南方铁路的工兵；其正前方司令构成阻挡，棋盘立即显示仍可到达的铁路网。
- Playwright 悬停一个 31 段外的合法落点后读取到完整 SVG 折线路径；路线从工兵位置出发，经南侧出口绕过阻挡后到达目标，没有穿过司令所在节点。
- 路线截图保存为本地 `output/playwright/acceptance/engineer-route.png`；该目录仍不纳入版本控制。
- 固定场景 `scenario=flag-capture` 与 `scenario=no-legal-move` 分别显示“西家军旗被擒获，全军覆没”和“北家无棋可走，全军覆没”，均未包含进攻棋子或身份对照。
- Playwright 创建房间 `873070` 后停止并重新启动服务端；原浏览器自动用原凭证恢复南家座位、昵称和 1/4 房间状态。故意停机期间的 WebSocket 连接失败符合预期；服务恢复后的新页面为 **0 error / 0 warning**。
- 后端自动化测试另以完整四人开局快照验证棋盘、阶段、修订号和四枚原凭证均可跨进程恢复，且持久化文件不含凭证明文。
