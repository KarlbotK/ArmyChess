# ArmyChess 产品需求文档

版本：1.0  
状态：MVP 需求基线；核心房间与对局链路已实现  
暂定产品名：**四国军棋 Online**

视觉基准：第二版“现代桌游”方案；棋盘结构以用户提供的经典四国军棋参考图为准。整体采用深绿毡面、暖白棋盘、克制木质细节和清晰中文棋子，避免军事指挥大屏式的压迫感。

当前实现覆盖：创建/加入私人房间、四人可编辑布阵与双重规则校验、服务端权威行棋、30 秒回合超时、四方视角旋转、落子后实际路线回放、暗棋裁剪、刷新与服务重启后的续局、聊天、投降、结算再战、健康检查与容器化。房主治理、内容安全服务、压力测试和生产监控按本文件的发布门槛继续推进。

## 1. 产品愿景

把旧版 Java 四国军棋改造成一个“打开链接就能和朋友开一局”的桌面优先 Web 产品。它保留原项目最有价值的四方棋盘、暗棋对抗和团队协作，同时补齐开房、邀请、断线恢复、规则引导、无障碍和可运营能力。

产品不是对旧 Swing 界面的简单换皮，而是对核心旅程的重建：

> 创建房间 → 邀请三位朋友 → 快速合规布阵 → 完成一局 → 查看结果并再来一局。

## 2. 目标用户

### 核心用户

- 熟悉军棋规则，希望和固定朋友在线对战的玩家；
- 在校园、家庭或社群中需要低门槛私人房间的组织者；
- 了解二人军棋，但第一次接触四国军棋的轻度玩家。

### 用户目标

- 不安装客户端，1 分钟内创建或加入房间；
- 清楚知道自己所属阵营、当前阶段和下一步；
- 在不泄露暗棋信息的前提下稳定完成一局；
- 断线后能回到原座位，不因刷新页面毁掉整局。

## 3. 产品目标与衡量指标

### MVP 目标

- 公开链接可访问，支持桌面浏览器与横屏平板；
- 私人房间完成四人真人对局；
- 服务端权威裁判，客户端无法通过构造请求修改规则；
- 一局结束后支持原房间再战。

### 目标指标

- 创建房间到成功分享邀请码：中位数小于 30 秒；
- 四人到齐到全部完成布阵：中位数小于 3 分钟；
- 非主动退出导致的对局中断率低于 1%；
- 刷新或短时断网后的座位恢复成功率高于 95%；
- 核心操作在 1280×720 视口不发生关键内容裁切；
- 自动化规则测试覆盖所有棋子战斗、铁路、行营、总部和胜负分支。

## 4. MVP 范围

### 4.1 首页与大厅

- 游客昵称进入，无需强制注册；
- 主操作只有“创建房间”和“输入房间码加入”；
- 展示一段精简玩法说明和完整规则入口；
- 记住最近昵称、音效和可访问性设置；
- 连接失败时提供明确原因、重试和服务状态。

验收：新用户不阅读外部说明即可创建房间，并复制有效邀请链接。

### 4.2 房间等待区

- 展示四个固定方位、两支队伍、玩家昵称和准备状态；
- 房主可移除未准备玩家、关闭空位或解散房间；
- 支持复制房间码与邀请链接；
- 玩家可选择空座；同队关系始终同时用位置、文字和颜色表达；
- 四人到齐并准备后，房主开始布阵。

验收：重复加入、房间已满、房间不存在和玩家掉线都有可恢复的明确反馈。

### 4.3 布阵

- 默认生成一套合法随机阵型；
- 支持点击交换与拖拽交换；
- 提供“重新随机”“恢复本轮初始阵型”“保存为本地预设”；
- 实时校验军旗、地雷、炸弹、行营和棋子数量；
- 非法位置在棋盘上直接标注，并给出具体修复文案；
- 提交后可在倒计时结束前撤回，所有玩家提交后进入对局。

验收：服务端独立校验完整阵型；修改前端代码或请求内容不能提交非法布局。

### 4.4 对局

- 棋盘始终以自己的阵地朝下显示；
- 顶部固定显示当前回合、玩家、剩余时间和网络状态；
- 选中棋子后只高亮合法落点，不铺开完整可达铁路网；服务端确认落子后，所有玩家短暂看到该步实际经过的路径；
- 工兵可在未被占用节点阻断的连通铁路上任意转弯和绕行；可攻击路径终点的敌棋，但不得穿过任何棋子；
- 无效操作在原位置给出短提示，不只写入聊天框；
- 战斗只通过棋盘状态变化和中性反馈呈现；公共战况不得出现“谁击败了谁”、交战双方棋子名称、胜方棋子身份或能够反推出暗棋的信息；
- 司令阵亡、军旗暴露和玩家出局仅在规则要求的范围内更新棋盘，不形成棋子身份对照表；
- 支持文字聊天与预设快捷语；默认限制长度和频率；
- 支持主动投降，危险操作需要二次确认；
- 支持 90 秒断线保留，重连后恢复私有棋盘视图和当前回合。

验收：任意客户端只能看到服务端允许的棋子身份；旁观网络请求也不能获得其他暗棋类型。浏览器网络面板、聊天、战况、通知和结算页均不得出现“谁击败了谁”的数据或文案。

### 4.5 结算与再战

- 明确显示获胜队伍和存活玩家；不展示关键战斗的棋子身份，不生成“谁击败了谁”的总结；
- 提供“原阵容再战”“返回大厅”；
- 再战重新进入准备和布阵，不复用上一局私有棋子信息；
- 本地保存最近 10 局的基础结果，不在 MVP 保存完整聊天记录。

### 4.6 规则与设置

- 规则页覆盖棋子强弱、特殊棋子、铁路、工兵、行营、总部、阵营与胜负；
- 首局提供可跳过的三步引导；
- 设置包含音效、动画强度、棋盘缩放、高对比度和色觉辅助标识；
- 键盘可完成选择、移动、聊天、打开规则和关闭对话框。

## 5. 核心状态机

`LOBBY → WAITING → LAYOUT → PLAYING → FINISHED → REMATCH_WAITING`

- 每次状态迁移只能由服务端确认；
- 客户端请求包含房间、玩家会话、动作和幂等标识；
- 非当前状态的请求被拒绝并返回可理解的错误码；
- 重连只恢复服务端已确认状态，不采用客户端本地棋盘作为事实来源。

## 6. 规则与公平性要求

- 服务端保存完整棋盘，向每位玩家发送裁剪后的视图；
- 布局必须校验 25 枚棋子及每类数量、owner、领地、军旗、地雷、炸弹和空行营；
- 移动前校验坐标边界、回合、归属、可移动类型、路径、目标格和阵营关系；
- 工兵与普通棋子的铁路路径分别测试；
- 战斗、出局、超时、投降和夺旗在服务端形成审计事件，但下发给客户端的公共事件必须脱敏；战斗事件不得包含 `attackerType`、`defenderType`、`winnerPiece` 或等价字段；
- 客户端战况最多显示“某方完成移动”“某位置发生交锋”“某方军旗被擒获，全军覆没”“某方无棋可走，全军覆没”等公开事实，不显示进攻棋子或棋子身份对战关系；
- 同一动作重复提交不能执行两次；
- 单方累计第 5 次回合超时后立即出局，移除该方全部棋子，并公开显示“累计超时 5 次，全军覆没”；
- 房间之间的计时器、玩家和结算完全隔离。

## 7. 非功能需求

### 安全

- 使用 HTTPS/WSS 和 JSON 消息，不接受 Java 原生序列化对象；
- 对消息结构、长度、频率和状态做服务端校验；
- 房间码不可顺序枚举，恢复凭证不可出现在公开日志；
- 聊天做长度限制、频率限制和基础内容安全处理；
- 依赖扫描、静态检查和密钥扫描进入持续集成。

### 可靠性

- 单房间异常不得停止进程或影响其他房间；
- 每次改变座位或棋局状态后原子写入未完成房间；服务退出时优雅关闭连接，重启后恢复房间、棋盘、回合、倒计时与再战票；
- 恢复凭证只在玩家浏览器保留原文，持久化文件仅保存 SHA-256 摘要；
- 日志带房间 ID、会话 ID、事件类型和错误码，不记录完整聊天、私有棋子或“谁击败了谁”的映射；
- 提供健康检查、房间数、连接数、动作错误率和异常率指标。

### 性能

- 首屏压缩资源目标小于 500 KB（不含按需加载音频）；
- 常规动作在正常网络下 200 ms 内得到服务端确认；
- 棋盘交互保持流畅，低性能设备可关闭非必要动画；
- 首个上线版本至少完成 100 个并发房间的压力验证。

### 可访问性

- 目标为 WCAG 2.2 AA 的核心交互要求；
- 颜色不是唯一状态线索；
- 所有控件有名称、焦点顺序和可见焦点；
- 回合、倒计时和战斗结果有非视觉可读文本；
- 支持 200% 缩放和减少动态效果偏好。

## 8. 技术方向

- **前端：React + TypeScript + Vite。** React 官方提供 TypeScript 使用路径，Vite 官方仍提供 `react-ts` 模板；适合高交互、无需服务端渲染的棋局界面。参考：[React TypeScript](https://react.dev/learn/typescript)、[Vite 官方指南](https://vite.dev/guide/)。
- **棋盘：DOM/SVG 混合或 Canvas。** 交互命中、缩放和状态覆盖必须与无障碍语义层分离，不能只绘制一张不可读的画布。
- **服务端：保留 Java 领域知识，迁移到 Spring Boot WebSocket。** 官方文档确认 Spring WebSocket 与 Boot 消息支持可用；协议使用显式 JSON DTO，而不是 Java 对象序列化。参考：[Spring Boot Messaging](https://docs.spring.io/spring-boot/reference/messaging/index.html)。
- **测试：** 规则引擎单元测试、协议集成测试、浏览器端端到端测试和多人并发模拟。
- **部署：** 前端静态资源与服务端容器化；开发、预发布、生产环境分离。

## 9. 信息架构

- `/`：首页 / 加入房间
- `/room/:code`：等待区与布阵阶段
- `/game/:id`：对局与结算
- `/rules`：规则
- `/settings`：本地设置

浏览器刷新后，路由与恢复凭证共同找回座位；无权限的用户不能通过猜测 URL 获得私有棋盘。

## 10. MVP 不做

- 排位、赛季、商城、皮肤交易；
- 公共语音聊天；
- 完整账号体系与跨设备战绩；
- 移动端竖屏完整对局；
- 全量对局录像分享；
- 机器人匹配（可作为上线后的首个留存功能）。

## 11. 发布门槛

- 所有 P0/P1 规则与安全问题关闭；
- 四人从创建房间到再战的端到端用例连续通过；
- Chrome、Edge、Safari 当前稳定版完成核心流程；
- 键盘流程与主流读屏器完成一次人工验收；
- 断线、刷新、重复消息、恶意坐标和非法布局测试通过；
- 隐私说明、使用条款、开源许可证和故障回滚方案齐备。
